# 原理说明

这套东西没有用任何私有的 SDK，全部走奇瑞官方 App 使用的公网接口。核心只有三件事：**拿到账号 token → 换成车辆 token → 用车辆 token 读车况/下车控指令**。

---

## 一、整体架构

```
            ┌──────────────── Android 手机 ────────────────┐
            │                                              │
 手机号+验证码 │  CheryLinker App                             │
 ──────────►│   ├─ UAA 登录（uaa2c.chery.cn）                │
            │   ├─ 车辆列表 / 车辆凭证（mobile-consumer-sapp）│
            │   ├─ 车况 / 车控（app-lioncloud.mychery.com）  │
            │   ├─ 桌面小组件（30 分钟自动刷新）              │
            │   └─ WearBridgeService（前台服务）             │
            └───────────────▲──────────────────────────────┘
                            │ 小米穿戴消息通道（蓝牙）
                            │ JSON 请求 / 响应
            ┌───────────────┴──────────────────────────────┐
            │  小米手表 · 快应用（Vela rpk）                │
            │  车况显示 / 按钮 / 手势                        │
            └──────────────────────────────────────────────┘
```

- **手机端**负责所有网络请求与签名，手表端完全不联网。
- **手表端**只把「要做什么」发一条消息给手机，手机执行完把结果回给手表。这么做是因为这类手表没有 Wi‑Fi，快应用的 `fetch` 只能借手机出公网，打不到手机本机的端口。

## 二、登录链路（实测）

### 1. 发验证码

```
POST https://uaa2c.chery.cn/api/v1/common/mobile/sms
Content-Type: application/json

{"mobile":"1XXXXXXXXXX","template":"login"}
```

同一号码 1 小时限 3 条，超出返回 `sms.captcha.only.three.send.within.one.hour`。

### 2. 验证码登录

```
POST https://uaa2c.chery.cn/api/v1/uaa/mobile/mobile-code-login
Content-Type: application/json

{"mobile":"1XXXXXXXXXX","verificationCode":"123456"}
```

成功返回（`data` 字段）：

| 字段 | 含义 |
| --- | --- |
| `accessToken` | 统一账号 token，后续接口放在 `Authorization: Bearer` |
| `refreshToken` | 刷新用，目前只保存未使用 |
| `expireAt` | 毫秒时间戳 |
| `openId` / `tenantId` / `source` | 账号标识，暂不需要 |

验证码字段名容易踩坑：写成 `code` 或传空会返回「请输入验证码」，只有 `verificationCode` 才是正确字段。

### 3. 车辆列表

```
GET https://mobile-consumer-sapp.chery.cn/web/chery/car-service/v2/car-manage/list
Authorization: Bearer <accessToken>
```

- 必须 **GET**（POST 会返回 `Request method 'POST' not supported`）；
- 必须带 `Bearer` 前缀（裸 token 会 401）；
- 不要加 `/api` 前缀（会 403）。

返回数组里每辆车包含 `vin`、`standardName`（如「风云A9」）、`licensenum`（车牌）、`isDefault`、`vehicleName`。App 按 `isDefault` 优先选默认车。

### 4. 换取车辆（NTSP）token

```
POST https://mobile-consumer-sapp.chery.cn/web/chery/car-service/v2/car-appsdk/getTspSdkToken
Authorization: Bearer <accessToken>
Content-Type: application/json

{}
```

返回 `data.sdk_token`（形如 `NTSPxxxxx.yyy.zzz` 的 JWT）、`appSecret`、`userId`。

注意：`data.appSecret` **不能**当作车况接口的签名密钥，它是另一个用途。签名密钥是下面那个全局常量。

## 三、车控接口的签名

LionCloud 的每个请求都要带 4 个 header：

| Header | 说明 |
| --- | --- |
| `Authorization` | 直接放 NTSP token（**不带** `Bearer`） |
| `timestamp` | 毫秒时间戳 |
| `nonce` | 随机串，服务端去重 |
| `x-App-Id` | 固定 `chery` |
| `sign` | 见下 |

签名算法：

```
payload = 按 key 升序把 body 拼成 "k1=v1&k2=v2"
        + "&secretKey=<全局密钥>"
        + "&nonce=<nonce>"
        + "&timestamp=<timestamp>"
        + "&x-App-Id=chery"

sign = UPPER(Base64(HMAC-SHA256(secretKey, payload)))
```

- 全局密钥：`de07173a4e4b35c3067fb5333e48e300`（所有账号通用，与登录无关）；
- 用 `appSecret` 签会返回 `A00877 签名验证失败`；
- Base64 结果要转成大写，不做大写服务端会拒。

## 四、车况

```
POST https://app-lioncloud.mychery.com/asd/v1/rt/data
{ "vin": "LXXXXXXXXXXXXXXXX" }
```

返回 `body` 节点里是车况原始字段：续航、电量、锁状态、车内温度、四轮胎压、总里程等。不同车型字段名不完全一样，[VehicleParser](../app/src/main/java/com/my/chery/data/VehicleData.kt) 里做了多候选字段兼容，App 首页底部「接口调试 → 查看原始数据」可以直接看这一坨 JSON 来补映射。

## 五、车控

统一入口：

```
POST https://app-lioncloud.mychery.com/asc/v1/vc/<feature>
{
  "clientType": 1,
  "seq": "<vin>-<时间戳>",
  "vin": "<vin>",
  ...各功能自己的参数
}
```

| 动作 | feature | 参数 |
| --- | --- | --- |
| 解锁 | `lockControl` | `lockType=1` |
| 上锁 | `lockControl` | `lockType=0` |
| 开后备箱 | `tailgateControl` | `controlType=1` |
| 关后备箱 | `tailgateControl` | `controlType=2` |
| 车窗通风 | `windowControl` | `controlType=2` |
| 空调 | `airControl` | `airControlType=1, airType=0` |
| 鸣笛寻车 | `findCar` | `state=3` |

返回码：

- `A00079` —— 指令已下发（**不代表车辆已执行**）；
- `A00082` —— 已有指令正在下发，稍后再试；
- 其他 —— 一般是权限、车辆休眠或签名问题。

车控是异步的：下发成功后车辆要 10~30 秒才动作，UI 上的状态需要再刷新一次才会变。

## 六、手表桥

`WearBridgeService` 是一个前台服务，用小米穿戴 SDK 注册消息通道；手表侧用 `@system.interconnect` 发消息。因为两边包名与签名一致，系统才允许互通。

请求格式（手表 → 手机）：

```json
{ "id": "<请求 id>", "path": "/status", "method": "GET", "body": {}, "token": "<内置访问口令>" }
```

手机 → 手表的响应结构相同，带 `code`、`message`、`data`。

| 路径 | 作用 |
| --- | --- |
| `/ping` | 连通性自检 |
| `/status` | 返回最近一次车况 |
| `/refresh` | 触发一次云端刷新后返回车况 |
| `/command` | 下发车控，`body.action` 指定动作 |
| `/gesture` | 手表手势上报，按手机端配置的手势映射执行 |

安全措施：

- 校验内置访问口令，不匹配返回 403；
- `/command` 校验一次性 `nonce`（重复直接拒），并限制保留数量防内存膨胀；
- 解锁类动作受手机端「允许手表解锁」开关控制，手表上还要二次确认；
- 手机上打开「观看」模式可以看到每一次请求与结果，排查用。

---

## 七、本地存储与桌面组件

- 手机号、账号 token、车辆 token、VIN、手势映射都存在 `SharedPreferences`（`chery_config`），不加密但也不出本机；
- 最近一次车况 JSON 也缓存一份，冷启动先显示旧数据；
- 桌面组件由 `WorkManager` 每 30 分钟唤醒一次拉车况并刷新 UI，点击组件可立即刷新。

## 八、逆向过程中踩过的坑（留档）

| 现象 | 原因 |
| --- | --- |
| 车辆列表 401 / 403 | 少 `Bearer` 前缀；或多加了 `/api` 前缀 |
| 车辆列表 405 | 接口只接受 GET |
| 车况 `A00877 签名验证失败` | 用了 `appSecret` 签名，正确做法是用全局 secretKey |
| `getTspSdkToken` 401 / 403 | 路径不是 `/api/web/...`，而是 `/web/...` |
| `Expected URL scheme 'http' or 'https'` | 相对路径被当成完整 URL 使用了 |
| 密码登录 `password.parse.error` | RSA 公钥已知，但明文 / hex / PKCS#1 / OAEP 都被拒，加密与填充方式仍未逆出，故暂不支持密码登录 |

## 九、稳定性与风险

- 以上接口是官方 App 的私有接口，**没有版本兼容承诺**，官方随时可能改字段、加风控；
- 频繁轮询有被风控的可能，App 默认只在打开页面、手动刷新、组件刷新时请求；
- 车控返回成功只表示云端已受理，车辆是否执行要看实车状态；
- 请只在本人车辆上使用。
