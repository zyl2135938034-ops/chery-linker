# CheryLinker · 奇瑞车控（手机 + 手表）

用**手机号 + 短信验证码**登录自己的奇瑞账号，直接在自建 App 里看实时车况、开关车门与后备箱，并能从小米手表上抬腕操作。

> ⚠️ 个人兴趣项目，**非奇瑞官方**。所有接口均由逆向官方 App 得到，随时可能失效；请仅在自己有权控制的车辆上使用。

---

## 功能

**手机端**
- 手机号 + 短信验证码登录，登录态保存在本机，下次打开免登录（token 失效时自动用已保存的账号凭证重新绑定，不用再发短信）
- 实时车况：续航、剩余电量、车锁状态、车内温度、四轮胎压、总里程
- 车控：解锁、上锁、开后备箱、关后备箱（已实车验证）；空调、鸣笛寻车、车窗通风（是否可用取决于车型与云端开放情况）
- 两个桌面小组件（车辆状态 / 续航），30 分钟自动刷新，也可点组件手动刷新
- 多车账号自动选中「默认车辆」

**手表端（小米 Vela 快应用）**
- 车况常显：车型、续航、电量、锁状态
- 解锁 / 上锁 / 后备箱 等按钮，手表端仍保留二次确认
- 手势映射：攥拳、捏合、顺/逆时针、推、拉，可分别绑到不同车控动作
- 手机端「观看」模式：手表卡片里能看到每一次请求的日志

## 快速开始

### 手机端

1. 把 APK 传到手机，允许「未知来源」后安装；
2. 打开 App，输入手机号 → 点「获取验证码」→ 填入短信验证码 → 登录；
3. 登录成功后会自动拉取车辆列表、选中默认车辆并进入首页，车况几秒内出现；
4. 想加桌面组件：长按桌面 → 小组件 → 找到「Chery Linker 车辆状态」或「Chery Linker 续航」。

> 短信验证码有频率限制：**同一号码 1 小时最多 3 条**。发满了就等一会儿，之前收到的验证码仍可直接用来登录。

### 手表端

1. 手机上装好「小米运动健康」，并保持与手表连接；
2. 手机装 AstroBox，取 AuthKey（小米运动健康 → 我的 → 关于 → 连点图标 10 次）；
3. 手表切到「设置 → 系统操作 → 连接新手机」；
4. AstroBox 连上手表，**先卸掉旧的「车控」**，再安装本仓库的 `.rpk`；
5. 手表上打开「车控」，几秒内状态点变绿即连通。手机端 App 需保持后台常驻（建议关闭电池优化）。

手表端与手机端必须满足两条硬性要求，发行包已经处理好：**包名一致（`com.chery.vehicontrol`）**、**签名一致**。自己重新打包时改坏任意一条，手机侧会直接拒收。

## 从源码构建

### 手机端

环境：JDK 17、Android SDK 34。

```bash
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

`assembleRelease` 需要自己的签名配置；仓库内不含任何 keystore。

### 手表端

手表端源码在 [watch/](watch/)，是小米快应用（Vela rpk）。用小米快应用打包工具重新打包，打包时必须：

- 包名与手机端一致：`com.chery.vehicontrol`
- 使用与手机 APK 相同的证书签名

否则手机会拒收手表发来的消息。

## 已知限制

- **只支持验证码登录**。密码登录接口（`/api/v1/uaa/login`）的密码加密方式尚未逆出（RSA 公钥已知，PKCS#1 / OAEP / hex 均被服务端拒绝），暂时没有做。
- 接口是逆向所得，奇瑞改动后端就可能失效。
- 车控指令是否被车辆接受，取决于车型、车联网服务是否开通、车辆是否在休眠。云端返回 `A00079` 只代表**已下发**，不代表车辆已执行。
- 手表端依赖小米穿戴的消息通道，手机端进程被系统杀掉会断连。

## 隐私

- 手机号、账号 token、车辆 token 只保存在本机 `SharedPreferences`，不经过任何第三方服务器。
- App 只直连奇瑞官方域名（`uaa2c.chery.cn`、`mobile-consumer-sapp.chery.cn`、`app-lioncloud.mychery.com`）。
- 仓库内不含任何真实账号、手机号或 token。
